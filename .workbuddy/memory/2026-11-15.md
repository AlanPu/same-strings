# 2026-11-15 · 同弦（same-strings）v1 交付

## 做了什么
按 `SPEC.md` 实现了「盲听辨人」训练器：8 位演奏家门德尔松 e 小调协奏曲，
7 段 × 8 人 = 56 个 25 秒片段，打成单文件 `dist/同弦.html`（21.79 MB）。
代码结构：`build.py` + `ssm/`（config/logbook/audio/span/warp/s0..s5/verify）+ `web/`（player.html/style.css/logic.js/app.js）+ `tools/`（诊断与冒烟）+ `tests/player_sim.js`。
12 项自动验收全过；4 项人工（#5 对齐试听、#6 选段试听、#8 离线、#11 存储降级）留材料在 `work/check/`。

## 关键决策（后续别推翻）
- **S1 增加了「有效演奏区间定位」**（`ssm/span.py`）。实测 8 条素材里 5 条带掌声/入场/返场，
  弗朗多出 **326 秒**（含返场）。不切掉的后果是掌声混进响度积分 + 全局 DTW 硬吞几分钟无关内容。
  做法：锚点 5 个位置各取 35 秒做探针 → 子序列 DTW 定位 → (锚点时间, 目标时间) 最小二乘外推起止。
- **响度统一目标落在 −24.23 LUFS，不是规格写的 −16**。原因：古典录音波峰因数大，
  弗朗那版 TP −1.65 dBFS，加 8 dB 就削顶。用「全体下移到共同可达水平」换取极差 0.030 LU，
  代价是整体偏安静 8 dB。**不做动态压缩**（会抹掉演奏动态，正是被测的东西）。
- **段内响度对齐必须双向**（S4）。最初写成「向最安静的一条看齐 + 最多衰减 9 dB」，
  结果既扭曲相对力度、又留下 13 dB 破题线索。改成以中位数为目标、受真峰值约束、增益限 [−15, +9]。
- **选段加了「速度一致性」约束**（S3，`max|drift| ≤ 2.5s`）。固定 25 秒下，
  局部速度差 20% 会让两段「同样 25 秒」覆盖的乐句量差一大截（实测帕尔曼某段 25 秒只走 18.6 秒音乐）。

## 踩过的坑（重要）
1. **ffprobe 的 `bit_rate` 是「字节数/时长」的实测均值**，AAC 内容自适应 → 56 个片段给 39 种码率值。
   验收判据应改成「编码参数 1 种 + 实测均值偏差 < 1.5%」，写「必须逐字节相同」是不可能达成的。
2. **DTW 路径的竖直段会被「取组内最后一个 y」放大成跳跃**（漂移 5.4s，且都是 1/3.5 的整数倍）。
   改用「anchor 时间 ±1s 窗口内取 y 中位数」重采样，抹平突跳、保留全局漂移。
3. **漂移本身是真实现象**，不是 warp 错：用独立局部 DTW 交叉验证，帕尔曼那段 cos 0.948、
   跨度 18.57s，确认是演奏速度差。所以手段是「避开这种段落」，不是「修 warp」。
4. **`segments.json` 与 `clips.json` 两份数据曾不一致**（S3 写的 segments 里 clips 是空的），
   导致验收 #15「演奏家覆盖」误报全员缺失。现在 S4 用 `_write_both()` 同时回写两个文件。
5. 无头浏览器验音频：`<audio>` 在 headless + virtual-time 下 `readyState` 恒为 0，是假阴性。
   改用 `canPlayType('audio/mp4; codecs="mp4a.40.2"')` + atob 字节数与 `bank.clips.bytes` 比对 + `ftypM4A` 头校验。

## 追加：可控性改造（顺序 / 选段 / 时长）
- **段数不再写死**：`config.max_clip_count(duration)` 由字节预算反推（BUDGET_MB=24、BYTES_PER_SEC=12400、
  base64 膨胀 4/3），`Project.segment_count = clamp(上限 // 人数, 5, maxCount)`。
  实测：20s→9 段、25s→7 段、30s→6 段、35s→5 段；8 人 5 段最长 37.8s。当前配置 **30s × 8 人 × 6 段 = 48 片段、22.41 MB**。
- **运行时「时长」是截断而不是重编码**：音频在构建期按 maxDuration 编好，运行到 `S.duration` 秒
  用 rAF 精确停（`timeupdate` 只有 4Hz，只在切后台时当兜底）。调短不增加体积，也不需要重新解码。
  iOS 上 `player.volume` 只读 → 没法做收尾淡出，只能是硬切，这点已在交付说明里讲明。
- **三种入口**：`buildSequential`（一段一题、按 bank 顺序）/ `buildSingle`（单段反复练，`avoid` 换人）/
  `buildRound`（原有的练习·考试·错题）。单段模式 `S.fixedSeg` 记住段落，「再来一题」不跳段。
- **验收表加了 #16**（顺序题数=段数 / 单段换人 / presets 含上限时长），#12 改成字节预算口径。
- **`build.py` 的 s4 签名原来写的是 `config.SEG_DURATION` 常量**，project.json 覆盖时长时缓存不会失效
  → 改 `proj.seg_duration`。这类「签名取常量不取工程值」的 bug 只在改配置时暴露，很容易漏。

## 追加：切分改为「从乐曲开头顺序切」
- **`segment.mode = "sequential"`（默认）**：第一刀固定在 0 秒，之后每刀 = 上一刀 + `stride`（缺省 0 → 等于 duration，首尾相接）。
  完全确定、无随机。`spread` 保留旧行为（乐章配额 + 最小间隔挑高分窗口）。
  刀口若落在静音/乐章边界上，只允许向后微移（≤30s）并写日志，移完按原步长继续。
- 因此 6 段 × 30 秒 = 前 3 分钟；要覆盖全曲就调 `segment.stride`（如 250），仍是从头、按序、可复现。
- 前端「从头开始」模式本来就是按 bank 顺序一段一题，和这个切分对得上。

## 这次挖出来的两个真问题（都不是「切分」本身）
1. **各版本开头的掌声/静场长度差到 80 秒**（哈恩 6.9s、哈德利希 52.9s、穆特 79.4s…）。
   以前实测的 drift 11~12 秒、头部速度比 4 倍，全是因为全局 DTW 的端点被这段非音乐内容硬拽。
   谱平坦度分不出「低电平的调音/空调声」和音乐（hahn 4.75s 那处是调音不是乐曲），
   改用**两两头部定位矩阵**：i 的开头会出现在 j 的第 (junk_j − junk_i) 秒，于是「行和最大」的
   那条就是废料最少（开头即音乐）的基准（实测选出 bell）。
2. **全局 DTW 的端点硬约束仍会把时长差挤到头部**（两版总长差 5s，头部就能畸形 3 倍速）。
   在 S2 加**头部局部校正**：用锚点开头 60s 做子序列匹配（无端点约束），替换 0~60s 的映射，
   60~90s 线性过渡回全局 warp，再单调化。校正后第 1 段内容偏移从 +6.8s 降到 −1.6s。

### 又踩到「缓存签名不含产物指纹」的坑
`--only s4` 用旧 segments.json 跑出 48 片段，却按新配置写下了 s4 的签名；
接着 `--from s3 --to s5` 时 S3 重跑了（53 段），S4 却「缓存命中」跳过，
于是 segments.json 是 53 段、clips.json 是 48 片段，#12 #15 直接对不上。

  端口也参数化 `"${PORT:-8080}:80"`。Compose 支持 `${VAR:-default}`；

- **nginx 必须跟着改**：参照页里是相对路径 `video/xxx.mp4`，挂到 `/ref/` 后变成

## 追加：交叉构建 x86_64 镜像
- `tools/docker_pack.sh`：buildx `--platform linux/amd64 --load` → `docker save | gzip`
  → `dist/docker/same-strings-amd64.tar.gz`（约 50 MB）+ sha256。
- **真正的价值是架构断言**：构建完 `docker image inspect --format '{{.Os}}/{{.Architecture}}'`
  比对请求值，不一致就中止。交叉构建典型失败是「静默产出宿主架构」而不是报错。
- tag 默认 `same-strings:latest`，必须和 compose 的 `image:` 对齐，
  否则 `docker compose up --no-build` 找不到、又回去 build。
- compose 加 `platform: ${TARGET_PLATFORM:-linux/amd64}`；本地跑原生 arm64 副本时覆盖。
- **无 docker 时怎么验脚本**：写一个桩 `docker`（实现 info / buildx version /
  buildx build / image inspect / tag / save），PATH 前置后跑全流程。
  三件事都验到了：正常路径退出 0、架构不符退出 1、PLATFORM 变了文件名跟着变。
  ⚠️ 桩测试抓到真 bug：`echo "  $OUT（$SIZE）"` —— **全角括号紧跟变量时 bash 会把
  多字节字符吃进变量名**，报 `OUT: unbound variable`（`set -u` 下直接退出）。
  脚本里凡变量后接中文/全角符号，一律写 `${VAR}`。
- 提交：`96fe09d`。

## 追加：参照页「哈德利希没声音」—— 其实是开场静场
- 排查顺序（值得复用）：先 `ffprobe -select_streams a` 看音轨在不在 → 全量
  `ffmpeg -v error -i x -f null -` 看解码错误 → `volumedetect` 看响度 →
  无头浏览器实测 `webkitAudioDecodedByteCount`。四关都过，说明不是文件/页面问题。
- **真因**：录像开头有静场。逐秒 RMS：哈德利希 0–20 s 在 −45…−53 dB（第 21 秒起乐），
  文格洛夫 31 s、穆特 36 s；哈恩一开就是 −24…−41 dB。对比音轨是裁过头的，所以
  「同一句对比」正常、「完整听」哑 —— 症状正好对上。
- 改法：`make_ref.py` 的 `music_start()` 实测起点（前 120 s、0.5 s 窗、95 百分位 −20 dB
  作阈值、连续 4 窗达标、回退 2 s），写进 data；前端点开时 seek 过去并提示跳了多少。
- ⚠️ 两个容易错的地方：`currentTime` 必须在 `loadedmetadata` 之后设（src 刚设时
  duration 是 NaN，硬设会被丢掉）；同一个源再次点击不触发 `loadedmetadata`，要单独走一条分支。
- ⚠️ 桩/无头验证用「页面 POST 回服务端」而不是 `--dump-dom`：`--virtual-time-budget`
  下媒体时钟不推进，`readyState/duration` 全是假阴性。真实时间 + POST 才测得到。
- ⚠️ `python tools/make_ref.py | head -14` 会把进程 SIGPIPE 掉，产物根本没写出来，
  而输出看着一切正常。**看管道输出的命令别加 head**。
- 提交：`afd328a`。

## 对比页：每段听几秒可选 + ‹ › 按段跳

- 需求：「同一句对比，可以让我设置播放多少秒，并且加一个跳转到上一段和跳转到下一段的按钮」。
- 时间轴从 0–100 百分比改成**按秒**（`min=0 max=round(total) step=1`）。百分比一格约 16 秒，
  太粗，‹ › 也就没法挪「你要的那几秒」。改完 `playOne`/`showPos` 里所有 `value/100*total` 都要跟着换。
- 秒数 chips：4/6/8/12/16/20/30，默认 8，存 `localStorage.ss.segSec`（隐私模式下 setItem 会抛，包 try）。
  轮播按钮文案跟着显示「各 N 秒」。
- ‹ › 按 `±segSec` 挪，夹在 `[0, total]`；**轮播中手动挪段要先 stopAll**，否则 playOne 的
  `then` 链断掉、轮播会停在半路。
- 验收：`check_ref.py` 加 3 项静态断言（控件齐全 / 滑杆按秒 / 默认值在预设表里）→ 24/24；
  再用真浏览器点一遍 17 项（含真出声：哈德利希 ref 600 s → 音轨 577.8 s）。
- ⚠️ 无头验证踩到两个坑：
  1) **页面的 8 个 `<audio>` 是 `createElement` 出来、没插进文档的**，`querySelectorAll('audio')`
     一个都拿不到，得在 `HTMLMediaElement.prototype.play` 上打补丁截获 `this`。
  2) **分段回报时 `while not RESULT` 会一收到中间态就退出**，音频那半段永远测不到；要认终态。
  3) Edge 已在跑时，不带独立 `--user-data-dir` 的新实例只是把标签页甩给现有窗口，进程立刻退出、
     回报永远不来。另：chromium headless shell 没有 AAC 解码器（真出声那项会假 FAIL），改用 Edge。
